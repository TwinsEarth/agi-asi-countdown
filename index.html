Headroom-Closed Index 能力余量闭合指数（HCI）

以某评测首次纳入年前沿（p90 得分）为基准、满分 100： HCI = (当前分 − 基准分) / (100 − 基准分) × 100。领域汇总：各评测当年 HCI 取 p90， 再按参与模型数平方根 √N 加权平均（兼顾覆盖度、避免大评测主导）。数据：Theseus Labs，2023–2026，393 组观测、10 大领域。

RSI 五级自主权框架（以「改进循环」为分析单元）

大模型评测基准（Benchmark）是什么

评测基准不是一张试卷，而是一套预先设计的测量规则，由四部分组成： ① 测试对象（测知识/推理/代码/对话还是工具使用）、② 测试数据（让模型答哪些题）、 ③ 执行协议（怎么提问、生成多长、给不给示例/工具）、④ 评分方法（怎么判好坏、怎么汇总）。 排行榜上的一个数字，是模型在这套特定规则下留下的一次测量结果，而不是模型的完整能力。
一句话流程：确定能力 → 准备题库 → 统一作答条件 → 收集回答 → 选择评分器 → 汇总结果与排名。点开每一步看要点。
1确定能力知识｜推理｜代码｜对话
“哪个模型最好”无法直接测量，要拆成具体目标：事实问答、数学逻辑推理、可运行代码、复杂指令遵循、长文本检索、安全/稳定/成本。 HELM 的思路是不只看准确率，而在不同场景同时观察校准、鲁棒性、公平性、偏见、毒性、效率等指标。
2准备题库公开数据｜人工案例｜动态新题
题目来自公开考试、专业数据集、人工案例、真实用户问题或程序动态生成。可靠题库要求：题目真的对应目标能力、难度能区分水平、 标准答案/评分标准清楚、覆盖多语言多行业，并防范数据污染——模型若在训练时见过题，就从“现场解题”变成“回忆答案”。 LiveBench 用定期更新的近期新题 + 尽量客观评分来降低污染。
3统一作答条件提示词｜参数｜工具权限｜模型版本
正式评测需固定：系统提示词与题目模板、是否给 few-shot 示例、温度与最大输出长度、是否允许联网/运行代码/调用工具、 每题运行一次还是多次、使用哪个模型版本与接口。一个能联网、一个不能联网，比的就不只是模型本身。
4收集回答同题运行｜必要时重复测试
在相同协议下让所有模型作答并留存原始输出；对随机性强、不稳定的任务要重复运行多次，才能估计结果的波动范围，而不是被一次运气误导。
5选择评分器标准答案｜规则测试｜模型裁判｜人类偏好
开放题与客观题需要不同评分器，四类评分器各有适用边界（见下方对照）。评分器本身的偏差会直接变成分数偏差。
6汇总结果单项得分｜权重｜总分｜排名
模型通常要答数百到数万题，先算每个任务的正确率/通过率/偏好胜率，再用平均、加权平均或统计模型合成总分。 这里最容易藏三个问题：各任务权重是否相同、总分是否掩盖明显短板、模型间微小差距是否具有统计显著性。

四类评分器（谁来打分）

① 标准答案评分

选择/计算/部分代码题，直接判对错
  • 优点：清楚、可复现
  • 风险：只适合有唯一答案的任务
  • 代表：MMLU 选择题

② 规则 / 测试用例

代码跑单测、结构校验格式、抽取比对字段
  • 优点：比文字匹配更贴近任务结果
  • 风险：测试用例可能覆盖不全
  • 代表：HumanEval/MBPP 单测

③ 大模型裁判

让另一个模型按标准评写作/总结/开放问答
  • 优点：快、成本低
  • 风险：位置偏差、冗长偏差、自我偏好
  • 代表：LLM-as-a-judge

④ 人类偏好评分

匿名两份回答二选一，大量比较形成排名
  • 优点：最贴近真实使用感受
  • 风险：受人群/题分布/票数影响，成本高
  • 代表：Chatbot Arena

基准测量重点 / 评分方式

为什么同一模型排名会变

不同排行榜可能使用不同的：能力定义、题目、提示词模板、生成参数、工具权限、裁判模型、汇总权重、模型版本。 “A 在某榜超过 B”只代表在这套题、协议与评分规则下A 更高，不能自动推出 A 在所有真实任务中都更好。
分数失真来源含义
数据污染测试题进入过训练集，考的是记忆
提示词敏感问法/模板/示例不同，答案就变
裁判偏差模型裁判偏好长答案、特定位置或自家风格
